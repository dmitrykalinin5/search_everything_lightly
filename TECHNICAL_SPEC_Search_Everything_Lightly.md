# Search Everything Lightly — техническое задание

## 1. Общая информация

**Название проекта:** Search Everything Lightly  
**Тип:** расширение GNOME Shell  
**Платформа:** Linux / GNOME Shell  
**Основной дистрибутив для разработки и тестирования:** Fedora  
**Язык интерфейса:** английский как основной, русская локализация — обязательно  
**Лицензия:** рекомендуется GPL-3.0-or-later  

## 2. Идея проекта

Search Everything Lightly — расширение GNOME Shell для максимально быстрого поиска файлов и папок по имени внешне напоминающее spotlight, но работающее как everything.

Расширение должно работать по принципу Everything для Windows:

- открываться по глобальной горячей клавише;
- показывать отдельное компактное окно поверх текущего рабочего стола;
- начинать поиск сразу при вводе текста;
- использовать индексированный поиск;
- мгновенно показывать подходящие файлы и папки;
- позволять открыть найденный объект клавишей Enter или мышью;
- поддерживать удобную навигацию с клавиатуры;
- визуально соответствовать GNOME.

Основной акцент проекта:

> быстрый поиск файлов без открытия GNOME Overview, Files или отдельного приложения.

## 3. Цели проекта

### 3.1. Основная цель

Создать удобный аналог Everything / Spotlight для GNOME Shell.

Пользователь должен иметь возможность:

1. нажать горячую клавишу;
2. начать вводить имя файла;
3. практически мгновенно получить результаты;
4. открыть нужный файл или папку.
5. менять горячие клавиши.

### 3.2. Дополнительные цели

Расширение должно:

- ощущаться как нативная часть GNOME;
- работать без заметных задержек;
- не блокировать GNOME Shell;
- не требовать постоянного ручного обновления базы;
- иметь минималистичный интерфейс;
- поддерживать дальнейшее расширение функциональности;
- в перспективе быть опубликовано на `extensions.gnome.org`.

## 4. Не входит в MVP

В первой версии НЕ требуется:

- поиск по содержимому файлов;
- собственный файловый индексатор;
- SQLite-база;
- облачный поиск;
- поиск внутри архивов;
- OCR;
- поиск по метаданным документов;
- AI / семантический поиск;
- интеграция с интернетом;
- синхронизация между устройствами.

Для MVP используется существующий индекс `plocate`.

## 5. Целевая аудитория

Пользователи GNOME, которым нужен:

- быстрый поиск файлов;
- аналог Everything;
- альтернатива стандартному поиску GNOME;
- отдельный Spotlight-подобный launcher;
- поиск без открытия Files;
- полностью клавиатурный workflow.

## 8. UI / UX

### 8.1. Окно

Окно должно:

- отображаться поверх остальных окон;
- появляться по центру экрана;
- иметь фиксированную или ограниченную максимальную ширину;
- адаптироваться под HiDPI;
- соответствовать текущей теме GNOME;
- иметь скругленные углы;
- иметь визуальное разделение между поисковой строкой и результатами.

Ориентировочная ширина:

```text
600–800 px
```

### 8.2. Поле поиска

Поле должно:

- автоматически получать фокус;
- иметь placeholder `Search files...`;
- очищаться при новом открытии окна;
- запускать поиск по мере ввода.

### 8.3. Результат поиска

Каждый результат содержит:

```text
[icon] filename.ext
       ~/path/to/file
```

Для папок:

```text
[folder icon] FolderName
              ~/Documents/...
```

### 8.4. Выбранный результат

Выбранный элемент должен иметь:

- визуальную подсветку;
- возможность выбора стрелками;
- открытие Enter;
- открытие кликом.

### 8.5. Поведение клавиш

| Клавиша | Действие |
|---|---|
| `Super + Space` | открыть / закрыть окно |
| `Esc` | закрыть окно |
| `↑` | предыдущий результат |
| `↓` | следующий результат |
| `Enter` | открыть выбранный файл |
| `Ctrl + Enter` | открыть родительскую папку |
| `Shift + Enter` | показать файл в файловом менеджере |
| `Ctrl + L` | вернуть фокус в поле поиска |
| `Ctrl + A` | выделить весь запрос |

## 9. Поисковый движок

### 9.1. MVP

Используется:

```text
plocate
```

Пример логики:

```bash
plocate --ignore-case --existing --limit 200 -- "query"
```

Поиск должен запускаться через асинхронный процесс.

Запрещено выполнять потенциально долгие операции синхронно внутри GNOME Shell.

### 9.2. Минимальная длина запроса

По умолчанию:

```text
3
```

Параметр должен позднее стать настраиваемым.

### 9.3. Ограничение результатов

По умолчанию:

```text
50
```

Для внутреннего ранжирования допускается получать больше кандидатов:

```text
200–500
```

После сортировки выводятся лучшие N результатов.

## 10. Ранжирование

`plocate` возвращает совпадения, но расширение должно дополнительно сортировать результаты.

Приоритет:

1. точное совпадение имени;
2. точное совпадение имени без расширения;
3. имя начинается с запроса;
4. запрос находится внутри имени;
5. совпадение только внутри пути.

Дополнительный приоритет:

1. `$HOME`;
2. пользовательские каталоги;
3. подключенные пользовательские диски;
4. системные директории.

Пример:

Запрос:

```text
lab3
```

Порядок:

```text
~/Documents/lab3.pdf
~/Documents/lab3/
~/Documents/physics_lab3_report.pdf
~/Downloads/archive-lab3.zip
/usr/share/.../lab3...
```

## 11. Дебаунс

Поиск НЕ должен запускаться на каждый символ мгновенно.

Использовать debounce:

```text
50–150 ms
```

Рекомендуемое стартовое значение:

```text
100 ms
```

Новый запрос должен отменять или игнорировать результат предыдущего запроса.

## 12. Работа с процессами

Расширение должно:

- запускать `plocate` асинхронно;
- не блокировать main loop GNOME Shell;
- корректно обрабатывать timeout;
- корректно обрабатывать отсутствие `plocate`;
- корректно обрабатывать пустой результат;
- предотвращать race condition между запросами.

Если пользователь быстро вводит `p → ph → phy → physics`, результат старого запроса не должен заменить результаты нового.

## 13. Проверка зависимостей

При запуске расширение должно проверить наличие:

```bash
plocate
```

Если `plocate` отсутствует, показать:

```text
plocate is not installed.
Install it to use Search Everything Lightly.
```

Для Fedora можно дополнительно показать:

```text
sudo dnf install plocate
```

Расширение НЕ должно самостоятельно запускать `sudo` или устанавливать пакеты.

## 14. Обновление индекса

Расширение не должно самостоятельно выполнять `updatedb` при каждом запуске.

Позже в настройках можно добавить:

- статус индекса;
- время последнего обновления;
- кнопку `Refresh index`.

Обновление должно происходить только по явному действию пользователя.

## 15. Открытие файлов

Использовать GNOME / Gio.

Стандартное действие:

```text
Enter → открыть URI / файл приложением по умолчанию
```

Для директории:

```text
Enter → открыть директорию в стандартном файловом менеджере
```

## 16. Reveal in Files

Для `Shift + Enter` расширение должно попытаться:

- открыть Files;
- выделить выбранный файл.

Если выделение недоступно — открыть родительскую директорию.

## 17. Иконки

Использовать MIME / Gio icon.

Примеры:

- папка → folder icon;
- PDF → PDF icon;
- изображение → image icon;
- видео → video icon;
- код → соответствующая MIME icon;
- неизвестный тип → generic file icon.

Не хранить собственный набор иконок для каждого MIME-типа.

## 18. Сокращение путей

Домашняя директория должна отображаться как `~`.

Пример:

```text
/home/username/Documents/file.pdf
```

показывается как:

```text
~/Documents/file.pdf
```

При слишком длинном пути допускается ellipsis.

## 27. Требования к `enable()` / `disable()`

При включении:

- зарегистрировать hotkey;
- создать необходимые объекты;
- загрузить настройки.

При отключении:

- удалить hotkey;
- закрыть overlay;
- завершить дочерние процессы;
- отключить signals;
- удалить таймеры;
- удалить references на UI;
- освободить ресурсы.

После `disable()` в GNOME Shell не должно оставаться ничего от расширения.

## 28. Требования к производительности

Открытие окна:

```text
< 100 ms
```

Начало отображения результатов:

```text
желательно < 200 ms
```

при готовой базе `plocate`.

UI должен оставаться отзывчивым независимо от поиска.

## 29. Обработка ошибок

Расширение должно корректно переживать:

- отсутствие `plocate`;
- поврежденную / отсутствующую locate DB;
- permission denied;
- недоступный путь;
- удаление файла между поиском и открытием;
- отключенный внешний диск;
- пустой запрос;
- очень длинный запрос;
- спецсимволы;
- Unicode;
- кириллицу;
- пробелы;
- кавычки;
- несколько быстрых запросов подряд.

## 30. Безопасность

Не формировать shell-команды через строковую конкатенацию.

Плохо:

```js
`plocate "${query}"`
```

Предпочтительно передавать аргументы процессу массивом.

Запрос пользователя не должен позволять выполнить произвольную shell-команду.

## 47. Критерии готовности MVP

MVP считается готовым, если пользователь может:

1. установить расширение;
2. включить его;
3. нажать горячую клавишу;
4. увидеть search overlay;
5. ввести минимум 3 символа;
6. получить результаты через `plocate`;
7. выбрать результат стрелками;
8. открыть его Enter;
9. закрыть окно Escape;
10. повторить процесс без лагов и ошибок.

## 48. Главный принцип проекта

Search Everything Lightly должен выполнять одну задачу максимально хорошо:

> мгновенно находить нужный файл или папку с клавиатуры.

Расширение не должно превращаться в универсальный launcher до того, как файловый поиск станет быстрым, стабильным и удобным.
